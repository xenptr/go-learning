## Key concepts

### What fuzzing is

Fuzzing is automated input generation for tests. The fuzzing engine:

1. Starts from your **seed corpus** (the inputs you provided with `f.Add`)
2. Mutates them — flipping bytes, inserting characters, combining inputs
3. Runs each mutation through your **fuzz target**
4. Tracks code coverage and keeps mutations that explore new paths
5. Reports any mutation that causes a panic or a `t.Error`/`t.Fatal`

It is especially good at finding edge cases that a human would never think
to write as a unit test, such as invalid UTF-8, zero-length inputs, or
very long strings.

---

### Unit test vs fuzz test — comparison

| | Unit test `TestXxx` | Fuzz test `FuzzXxx` |
|---|---|---|
| Input source | Hand-written by developer | Generated by the engine |
| Output known in advance? | Yes | No — test properties instead |
| Finds known bugs | Yes | Yes |
| Finds unknown edge cases | No | Yes |
| Deterministic | Yes | No (engine is random) |
| Speed | Fast | Slow (runs indefinitely) |
| Function signature | `func TestXxx(t *testing.T)` | `func FuzzXxx(f *testing.F)` |

You can keep both in the same `_test.go` file.

---

### Fuzz test anatomy

```go
func FuzzReverse(f *testing.F) {
    // 1. Seed corpus — engine starts here and mutates from these
    f.Add("Hello, world")
    f.Add(" ")

    // 2. Fuzz target — called once per generated input
    f.Fuzz(func(t *testing.T, orig string) {
        // 3. Exercise the code under test
        rev, err := Reverse(orig)
        if err != nil {
            return  // or t.Skip() — skip invalid inputs, don't fail
        }

        // 4. Assert properties (invariants), not exact values
        doubleRev, _ := Reverse(rev)
        if orig != doubleRev {
            t.Errorf("double-reverse failed: %q → %q", orig, doubleRev)
        }
    })
}
```

### Property-based testing

When fuzzing you can't predict what input the engine will generate, so you
can't hard-code an expected output. Instead you check **properties** —
things that must always be true regardless of the input:

| Property | What it catches |
|---|---|
| `Reverse(Reverse(s)) == s` | information loss, byte corruption |
| `utf8.ValidString(rev)` when input is valid | encoding corruption |

Think of properties as contracts: "for ANY valid input, these facts hold."
If the engine breaks a contract, it has found a real bug.

---

### The two bugs this tutorial finds

#### Bug 1 — byte-wise reversal corrupts multi-byte UTF-8

```go
// BUGGY — reverses raw bytes
b := []byte(s)
// swap b[i] and b[j]...

// A character like 泃 is encoded as 3 bytes: E6 B3 83
// Reversing the bytes gives 83 B3 E6 — not valid UTF-8
```

**Root cause:** UTF-8 is a variable-width encoding. Characters outside ASCII
use 2–4 bytes. Swapping individual bytes scrambles the byte sequences that
form those characters.

**Fix:** convert to `[]rune` first. Each rune is one Unicode code point
regardless of how many bytes it occupies. Swapping runes preserves encoding.

```go
r := []rune(s)   // decode UTF-8 → code points
// swap r[i] and r[j]...
return string(r) // encode code points → UTF-8
```

#### Bug 2 — invalid UTF-8 input gets silently mutated

```go
// Input: "\x91"  (one byte, not valid UTF-8)
r := []rune("\x91")
// Go replaces the invalid byte with U+FFFD (the replacement character '�')
// r = ['�']
// Reverse of ['�'] is ['�']
// string(['�']) = "ef bf bd" (3 bytes) ≠ original "\x91" (1 byte)
```

**Root cause:** Go's `[]rune()` conversion replaces invalid bytes with `'�'`
rather than preserving them. Double-reversing produces `'�'`, not the
original byte.

**Fix:** validate the input before doing anything. Return an error on
invalid UTF-8 so the contract is explicit:

```go
if !utf8.ValidString(s) {
    return s, errors.New("input is not valid UTF-8")
}
```

---

### Bytes vs runes vs strings in Go

| Type | What it holds | Example for '泃' |
|---|---|---|
| `string` | read-only byte sequence (UTF-8) | `"\xe6\xb3\x83"` (3 bytes) |
| `[]byte` | mutable byte sequence | `[0xe6, 0xb3, 0x83]` |
| `[]rune` | Unicode code points (int32) | `[0x6cc3]` (1 rune) |

Converting `string → []byte` and back is safe only for ASCII.
For Unicode text, always convert to `[]rune` when you need to index or
reverse by character.

### Saved corpus files

When the engine finds a failure, it writes the input to:

```
testdata/fuzz/FuzzReverse/<hash>
```

Format:

```
go test fuzz v1
string("泃")
```

- Line 1: encoding version
- Each subsequent line: one argument to the fuzz target, in order

This file is committed to source control (or at least not `.gitignore`d).
On every future `go test` run it is replayed automatically — the failing
case becomes a permanent regression test.

---

### Useful fuzzing flags

| Flag | Effect |
|---|---|
| `-fuzz=FuzzReverse` | enable the fuzzing engine for this test |
| `-fuzztime 30s` | stop after 30 seconds if no failure |
| `-fuzztime 1000x` | stop after 1000 iterations |
| `-run=FuzzReverse/<hash>` | replay one specific saved input |
| `-v` | print `t.Log` output even when tests pass |
